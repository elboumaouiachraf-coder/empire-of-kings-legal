2. Données utilisées

  • Compte : adresse e-mail, identifiant unique, pseudo et informations nécessaires à l'authentification. Le mot de passe est transmis à Supabase Auth via HTTPS ; Supabase utilise des empreintes cryptographiques pour son stockage. Le code applicatif audité ne prévoit pas de stockage volontaire du mot de passe en clair.
  • Jeu connecté : château, niveau, coordonnées dans le monde fictif, données de progression disponibles côté serveur, commandes de jeu, marches et rapports associés au compte.
  • Communication : lorsque les fonctions correspondantes sont disponibles, messages, auteurs, dates et adhésions aux alliances. [Activation effective à confirmer avant publication.]
  • Fonctionnement technique : identifiants de requête, dates d'opérations et données nécessaires aux connexions. Les prestataires réseau reçoivent notamment l'adresse IP ; des événements d'authentification peuvent être journalisés.
  • Service client : adresse e-mail de l'expéditeur et contenu des échanges que vous choisissez d'envoyer. Ne transmettez aucun mot de passe ou jeton de connexion.

Les coordonnées des châteaux sont fictives : elles ne correspondent pas à votre position géographique. Aucune permission Android de localisation, caméra, microphone ou contacts n'a été identifiée dans V26.

Les données servent à authentifier le joueur, retrouver son royaume, afficher la carte partagée, fournir les fonctions de jeu disponibles, répondre aux demandes et sécuriser le service contre les accès frauduleux et les opérations dupliquées.

4. Informations visibles dans le jeu

Le pseudo, le nom du château, son niveau et ses coordonnées fictives, ainsi que certaines informations de marches publiques (propriétaire, type, trajet et horaires), peuvent être visibles par les autres joueurs autorisés. Les messages sont visibles selon leur canal et les droits applicables.

L'adresse e-mail, le mot de passe et les jetons de session ne sont pas destinés à être publics. Le filtre client des marches ne transmet pas à l'affichage public les effectifs privés ni les marches d'espionnage d'un autre joueur ; les règles serveur doivent également protéger ces informations.

5. Stockage sur l'appareil

L'application conserve des réglages, des sauvegardes locales et des informations de session dans le stockage de la WebView et, selon les fonctions, dans une base locale. La session en ligne peut rester active entre deux ouvertures. Aucun coffre applicatif chiffré dédié aux jetons n'a été identifié.

La progression solo est distincte des données du compte multijoueur et n'est pas automatiquement importée. Effacer les données locales ou désinstaller le jeu ne supprime pas le compte en ligne. Les exports de sauvegarde effectués volontairement par le joueur restent sous son contrôle.

6. Prestataires, destinataires et hébergement

La version V26 utilise exclusivement l'environnement Supabase TEST pour les comptes et les données en ligne. Supabase fournit l'authentification et la base de données. Cloudflare Pages est référencé pour les pages Web de retour de confirmation ou de récupération du compte. Les demandes au service client sont reçues via Gmail, service de Google.

Les données nécessaires peuvent être traitées par ces prestataires et par les personnes autorisées chargées de l'exploitation et du support. Les affichages publics dans le jeu sont décrits à la section 4.
